# Documentación técnica

- Inspecciona primero README, docs existentes, comentarios y convenciones del repositorio.
- Actualiza documentos existentes en vez de duplicarlos o reemplazarlos sin motivo.
- Documenta propósito, arquitectura, flujos, contratos, configuración por nombre de variable, pruebas y operación segura.
- No escribas valores de secretos, tokens, URLs privadas con credenciales ni datos personales.
- Marca claramente implementado, parcial, no disponible, experimental y roadmap.
- No describas un endpoint, pantalla, integración o servicio como operativo sin verificarlo en código y pruebas.
- Incluye ejemplos reproducibles y seguros; evita comandos destructivos o de producción sin advertencia.
- Mantén diagramas y mapas de contexto consistentes con la arquitectura real.
- Cuando cambie materialmente la arquitectura, actualiza el resumen persistente del proyecto sin incluir secretos.
